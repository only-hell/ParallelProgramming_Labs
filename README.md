# Лабораторная работа №1: Последовательные вычисления

## 1. Постановка задачи
Целью данной работы является реализация алгоритма перемножения двух квадратных матриц $A$ и $B$ размерности $N \times N$. Программа должна считывать исходные данные из текстовых файлов, выполнять вычисления, фиксировать время работы вычислительного ядра и сохранять результирующую матрицу в файл. Также требовалась реализация механизма автоматической верификации для исключения вычислительных ошибок.

## 2. Методика реализации
Программное решение реализовано на языке C++ с применением стандартной библиотеки `<chrono>` для высокоточного измерения времени. Матрицы представлены в виде одномерных динамических векторов (`std::vector<double>`), что обеспечивает эффективное использование кэш-памяти процессора за счет последовательного размещения данных.

Для верификации был разработан вспомогательный скрипт на языке Python. Он использует библиотеку `numpy` для эталонного умножения матриц. Процесс проверки включает:
1. Загрузку данных из файлов, сформированных C++ программой.
2. Сравнение результатов с использованием метода `np.allclose`, который учитывает малые погрешности вычислений с плавающей точкой (типа `double`).

## 3. Анализ производительности
Эксперименты проводились путем многократного запуска программы для каждой размерности матриц. Средние значения времени приведены в таблице ниже:

| Размер (N) | Число операций (~$2N^3$) | Среднее время (сек) | Верификация |
| :--- | :--- | :--- | :--- |
| 400 | $1.28 \cdot 10^8$ | 0.315 | ✅ Успешно |
| 800 | $1.02 \cdot 10^9$ | 2.437 | ✅ Успешно |
| 1200 | $3.46 \cdot 10^9$ | 9.597 | ✅ Успешно |

*Примечание: общее число операций для умножения матриц $N \times N$ составляет $2N^3$ (умножение + сложение для каждого элемента).*

## 4. Заключение
В процессе выполнения работы было подтверждено, что время выполнения алгоритма перемножения матриц пропорционально $N^3$. Данный факт наглядно демонстрирует, почему для решения задач большой размерности (N > 1000) необходимо применение методов параллельного программирования (OpenMP, MPI, CUDA), так как последовательная реализация обладает низкой масштабируемостью при росте объема входных данных.
